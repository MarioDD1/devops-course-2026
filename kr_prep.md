# Подготовка к контрольной работе

## Когда выбрать rebase или merge
Rebase использую для своей неопубликованной ветки, когда нужна линейная история. Merge сохраняет историю параллельной разработки и подходит для общих веток.

## Rebase публичной ветки
Rebase меняет хеши коммитов. У коллег останется старая история, поэтому возникнут расхождения и потребуется согласованное восстановление веток.

## Зачем нужен multi-remote
Несколько remote позволяют хранить резервную копию, синхронизировать GitHub и GitLab и отдельно работать с исходным проектом и fork. Для push в два репозитория у origin явно задаются оба push-URL.
